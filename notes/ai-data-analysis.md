## 一、核心主题一句话

> **AI 数据分析不是"让 AI 帮你画个图表"，而是"让 AI 发现人类发现不了的隐性数据关系"——但前提是，你的底层数据要拆得足够细。**

## 二、AI + 数据分析的两个核心问题

```
问题 1：作为个人用户
├─ 我不建平台
├─ 只想知道：AI 有哪些工具能帮我做数据分析？
└─ 答案：Chat Excel、JustBuk、WPS AI 等工具

问题 2：作为产品经理
├─ 我想把 AI + 数据分析做成产品
├─ 给更多人用（企业内部 / 面向客户）
└─ 答案：需要搭建智能数据平台（参考三阶段模型）
```

## 三、数据分析的四个维度

| 维度 | 说明 | 举例 |
|------|------|------|
| **大数据分析** | 用户标签、行为、趋势 | 分析用户画像、业务走势 |
| **AI 模拟验证** | 用模拟数据验证模型/预测 ROI | 项目立项前预测收益 |
| **实时反馈分析** | 对用户行为/反馈做实时监测 | 用户评论情感分析、实时预警 |
| **AI 预测模型** | 预测未来趋势 | 库存预测、销量预测、用户行为预测 |

### 项目立项的验证路径

```
立项前：模拟数据 → 预估 ROI
  ↓
上线后：真实数据 → 验证之前的结论是否准确
  ↓
持续优化：实时数据 → AI 分析 → 调整策略
```

## 四、用户标签体系：腾讯的例子

### 标签的分层结构

```
基础标签（各业务通用）
├─ QQ 号 → 性别、地理位置、办公位置
├─ 设备信息、登录偏好
└─ 户籍地等基础属性

业务标签（各产品独立）
├─ QQ 音乐 → 听歌偏好、收藏列表
├─ 腾讯视频 → 观看记录、付费行为
├─ QQ 阅读 → 阅读偏好、阅读时长
└─ 各产品数据目前未打通
```

### 理想 vs 现实

> **理想**：用户在 QQ 音乐常听《盗墓笔记》主题曲 → 腾讯视频自动推荐相关演员主演的影视剧
>
> **现实**：内部账号体系未打通，很难实现跨产品关联推荐

### 标签设计的关键细节

| 要素 | 说明 |
|------|------|
| 口径定义 | 每个标签的计算逻辑必须明确 |
| 数据来源 | 标签的数据从哪来 |
| 更新频次 | 每次更新的时间点和频次差异 |
| 时间影响 | 不同时间阶段可能影响策略执行 |

> 💡 **血泪教训**：底层复杂的数据内容和口径问题，曾经让团队吃了不少亏。

## 五、AI 数据分析工具推荐

| 工具 | 能力 | 评价 |
|------|------|------|
| **Chat Excel** | 上传 Excel → 自然语言提问 → 计算/筛选/可视化 | 推荐 ✅ |
| **JustBuk Excel Agent** | 类似 Chat Excel 的能力 | 推荐 ✅ |
| **WPS AI 数据分析** | 内置 AI 分析功能 | 准确率不到 50% ❌ |
| **神策数据** | 专业数据平台，有标准化指标定义 | 成熟方案 ✅ |
| **自定义公式（LAMBDA）** | 用自然语言描述需求 → 生成自定义函数 | 高阶用法 ✅ |

### Chat Excel 的亮点

```
上传表格 → 自然语言对话
├─ 自动计算（求和、平均、占比等）
├─ 表格合并、筛选
├─ 自动生成可视化图表
└─ 每个步骤有清晰编号路径，可追溯
```

### WPS AI 的问题

> 体验后准确率非常低，可能不到一半。但它的存在说明：现在许多 AI 办公工具都在整合基础分析能力。
>
> **启发**：方向对了，但当前实现质量参差不齐，选型时务必实测。

## 六、智能数据平台三阶段

```
    1.0               2.0               3.0
┌──────────┐    ┌──────────────┐    ┌──────────────┐
│ 查表取数  │ ──→│ 报表+可视化   │ ──→│ 业务归因分析  │
│ Text2SQL │    │ 自然语言建表  │    │ 理解业务逻辑  │
└──────────┘    └──────────────┘    └──────────────┘
  大部分企业       部分企业在用        目前很难实现
  能做到                              （需专家经验）
```

### 各阶段问题类型对比

| 阶段 | 典型问题 | 难度 |
|------|---------|------|
| **1.0** | "最近 7 天 XX 产品的订单总量是多少？" | ⭐ |
| **2.0** | "帮我生成一个按渠道分的销售报表" | ⭐⭐ |
| **3.0** | "华北地区 XX 产品销量月环比为什么下降了？" | ⭐⭐⭐ |

### 3.0 为什么难？

1. 需要业务专家提供归因规则
2. 不同人对同一指标的口径理解不同
3. 维度间的散状依赖关系复杂
4. 需要业务专家的隐性知识（"一个人能做好，不代表能教 AI 做"）

## 七、数据平台架构要素

```
┌────────────────────────────────────────────┐
│              智能数据平台                    │
├──────────────┬──────────────┬──────────────┤
│  基础数据层   │  聚合计算引擎 │  语义标准化   │
│  ├ 产品维度  │  ├ 求和/平均  │  ├ "月环比"   │
│  ├ 渠道维度  │  ├ 环比/同比  │  │  的统一定义│
│  ├ 用户维度  │  └ 自定义函数  │  └ 口径对齐   │
│  └ 时间维度  │              │              │
├──────────────┼──────────────┼──────────────┤
│  跨域处理     │  权限控制     │  多任务系统   │
│  国内/海外隔离 │  数据权限校验 │  依赖关系处理 │
└──────────────┴──────────────┴──────────────┘
```

### 容易忽略的关键点

| 问题 | 说明 |
|------|------|
| **口径统一** | "月环比"在不同业务中定义可能不同（1 号到 30 号 vs 15 号到 15 号） |
| **数据权限** | 先校验用户权限，再允许数据读取 |
| **国内/海外隔离** | 海外数据不能直接进入国内系统，需要额外包装 |
| **多任务依赖** | 先做第一次分析，再基于结果做第二次分析 |

## 八、实战案例：AI 内容出海项目

### 项目概述

```
国内短篇小说 → AI 改写（适配海外市场）
     ↓
AI 有声书生成（多角色配音，CozyVoice TTS）
     ↓
AI 分镜 + 图片生成 → AI 视频
     ↓
海外平台分发（类似海外版喜马拉雅/红果短剧）
```

### 为什么选择海外？

| 因素 | 说明 |
|------|------|
| 国内听众成熟 | 宫斗剧情大家能预测结局 |
| 海外听众新鲜感强 | "狼人""吸血鬼"版的宫斗，海外用户很喜欢 |
| 内容成本低 | 无编剧/编辑/作者，全 AI 生产 |
| 版权灵活 | 使用版权不敏感内容（低调运行） |

### 技术演进：从人工到 AI

```
2020 年（人工为主）：
├─ NLP 规则定位音效插入点
├─ 人工清洗 8000+ 特效音
├─ 每个音效精调 0.3-0.5 秒
├─ 人工匹配角色音色
└─ 耗时：大半年

2023 年（AI 为主）：
├─ 大模型自动分析 → 确定音效插入点
├─ AI 自动匹配配音（从上万候选中）
├─ MiniMax 等模型直接生成特效音
├─ 时间戳自动对齐
└─ 效率提升 10 倍以上
```

> 💡 **关键教训**：2020 年投入大量人力做的技术工作，到 2023 年被 AI 完全替代。
>
> **经验**：如果你判断 3-6 个月内会有更好的开源工具出现，就不要把人力浪费在技术实现上——重点放在增长和商业化。

## 九、增长与商业化的数据驱动

### 增长策略

| 策略 | 方法 | 数据指标 |
|------|------|---------|
| 付费投流 | Facebook 广告 | 获客成本（2-3 美元/用户） |
| KOL 推广 | TikTok 达人发视频导流 | 视频热度周期（约 1 周） |
| MCN 合作 | 搭建达人管理平台 | 达人产出、转化率、反作弊 |
| CPS 分佣 | 口令词/推广码追踪 | 推广归因、佣金结算 |

### 商业化数据拆解（极致细致）

```
内容维度
├─ 每部作品 → 每集 → 到达率、完播率、跳过率
├─ 付费内容触达次数 → 转化意愿度
└─ 不同国家 × 不同内容 → 偏好差异

用户维度
├─ 听了什么、听了多少集、哪些没听完
├─ 哪些直接跳过、听到付费点几次
└─ 为什么没转化？

运营维度
├─ 每个渠道的播放时长
├─ 哪些 KOL 产出价值最高
├─ 哪些营销素材带来最多用户
└─ 每个内容生产环节的成本效率

商业化维度
├─ 不同国家的定价策略（阶梯定价）
├─ 不同用户群的折扣策略
└─ 定价持续时间 → 续费分析
```

> 💡 **数据颗粒度**：十几个工作群，每个群播报不同维度的数据。每天早上开晨会对齐。每个环节都做到极致细致。

## 十、快速验证方法论

### 分享者的风格

> **"先小范围验证，再精细化。"**
>
> 不做复杂 BRD 直接报批——先用最小成本跑通模式，有数据了再汇报。

### 实践路径

```
Step 1：用最小成本做原型 Demo
├─ 收款账户？自己用 Stripe 注册一个
├─ 不做 PR，低调运行
└─ 30 人团队（每人投入 0.3-0.5 人力）

Step 2：验证模式是否可行
├─ 有数据支撑 → 值得投入
└─ 跑不通 → 快速放弃，换方向

Step 3：模式验证成功 → 精细化运营
├─ 合规化（替换个人账户）
├─ 扩大团队
└─ 内部正式立项
```

### 关于技术投入的判断

> **"如果 3 个月内能获得现成的技术能力，就直接用。重点放在业务和商业化上。"**
>
> 内部的速度永远赶不上外部。技术投入要克制，把精力放在增长上。

## 十一、数据分析指标拆解思路

### 通用框架（以 ToC 场景为例）

```
拉新 → 活跃 → 留存 → 转化 → 付费

每个阶段细拆：
├─ 拉新：渠道来源、获客成本、首日行为
├─ 活跃：DAU、使用时长、功能渗透率
├─ 留存：次日/7日/30日留存、流失原因
├─ 转化：转化路径、转化漏斗、转化率
└─ 付费：付费率、ARPU、LTV
```

### 关键发现案例

> 腾讯视频发现：新用户在**第 4-5 天**如果有 **2-3 个以上好友**，对 LTV 有显著提升。
>
> 这种隐性关系不容易被发现，需要人工结合多张表做交叉分析。
>
> **理想**：AI 能自动发现这类隐性关系，并建议干预措施。

### 对产品经理的要求

> 即使你不是运营人员，也需要具备数据分析的意识：
> - 知道业务从哪些维度拆解
> - 了解产品和业务维度的细致拆法
> - 在每个流程节点上还能继续细分

## 十二、关键术语表

| 术语 | 含义 |
|------|------|
| **Text2SQL** | 自然语言转 SQL 查询 |
| **Chat Excel** | 通过对话操作 Excel 表格的 AI 工具 |
| **LAMBDA** | Excel/表格中的自定义函数能力 |
| **LTV** | Life Time Value，用户生命周期价值 |
| **ARPU** | Average Revenue Per User，每用户平均收入 |
| **CPS** | Cost Per Sale，按销售付费的推广模式 |
| **MCN** | Multi-Channel Network，达人/网红经纪机构 |
| **KOL/KOC** | 关键意见领袖/关键意见消费者 |
| **归因分析** | 分析"为什么某个指标变了"的深层原因 |
| **CozyVoice** | 阿里的开源 TTS（文字转语音）模型 |
| **神策** | 国内知名数据分析平台 |
| **七麦数据** | APP 数据追踪平台（记录版本历史、排名等） |
| **BRD** | Business Requirement Document，商业需求文档 |
