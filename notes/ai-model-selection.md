## 一、核心主题一句话

> **大多数公司不该自研模型——先用好第三方 API，把精力花在"选对模型"和"建好评测"上。**

---

## 二、自研 vs 第三方 API：算一笔账

### 自研的三大成本

```
┌─────────────┬────────────────────────────────────────┐
│  成本项      │  说明                                  │
├─────────────┼────────────────────────────────────────┤
│  算力成本    │  H20 租赁约 3-4 万/月/卡（不含购买）    │
│  人才成本    │  AI 算法专家年薪 50-200 万不等          │
│  时间成本    │  投入数千万，结果可能仅追平开源模型      │
└─────────────┴────────────────────────────────────────┘
```

### 真实案例

> 团队在 2023 年投入**数千万**做垂类模型，最终成果可能仅相当于 DeepSeek 等通用模型的水平。
>
> **结论**：除非是头部大厂承担战略任务，否则大多数公司不推荐自研。

| 背景 | 期望月薪 | 备注 |

## 五、第一步：算经济账

选型时需要计算的全部成本：

| 成本项 | 说明 |
|--------|------|
| **API 调用费** | 百万 token 低至不到 1 元（基础模型） |
| **Token 消耗量** | 输入 token + 输出 token 分别计价 |
| **部署成本** | 如果要自己部署开源模型（如 CozyVoice TTS） |
| **微调成本** | 模型微调（Fine-tuning）的计算和人力成本 |
| **维护成本** | 长期运维、版本升级的人力成本 |

### 常用 API 来源

| 来源 | 举例 | 特点 |
|------|------|------|
| 通义系列 | Qwen 各版本 | 开源可部署，也可 API 调用 |
| DeepSeek | DeepSeek-V3/R1 | 性价比高，2025 年初大热 |
| 火山引擎 | 字节系模型 | API 接入成本低 |
| CozyVoice | 阿里 TTS | 语音合成效果好 |

> 💡 **关键点**：不仅看 API 单价，还要算上部署、微调、维护等隐性成本。先把经济账算清楚，再比效果。

## 六、第二步：看评测榜单

### 榜单的分类

| 类型 | 说明 | 适合场景 |
|------|------|---------|
| **通用能力榜单** | SuperCrew 等综合排名 | 初步筛选模型 |
| **安全评估** | 模型安全性、合规性 | 面向 C 端的产品 |
| **多语言能力** | 跨语种表现评估 | 出海业务 |
| **垂类评估** | TTS、视觉、代码等专项 | 特定技术选型 |

### 看榜单的注意事项

```
✅ 榜单可以作为初步筛选的参考
✅ 关注不同维度（推理/代码/多语言/安全）
⚠️ 模型厂商发布时自带排行榜 → 有宣传成分，需甄别
⚠️ 不同榜单评测标准不同 → 不能简单横向对比
```

## 七、第三步：实际体验评测

### 评测的三个层次

```
层次 1：自己用一用
   ↓   最直观，但样本太少
层次 2：团队一起测
   ↓   不同人用不同评测集（长文本/多模态/其他）
层次 3：技术维度深度评估
         让专门的技术同学做更复杂的多维评估
```

### TTS 评测实例

分享者团队曾使用 **2000 句测试集**，评估维度包括：

- 数字读取（电话号码、银行卡金额）
- 多语言处理
- 情感表达
- 自然度和流畅度

> 💡 **原则**：评测不能只靠产品经理自己，要让技术同学深入参与。

## 八、第四步：业务专属测试集

### 为什么需要自己的测试集？

| 公开榜单 | 业务测试集 |
|---------|-----------|
| 通用场景 | **你的具体业务场景** |
| 标准化题目 | **你的真实用户问题** |
| 横向对比模型 | **纵向追踪模型在你场景的表现** |

### 如何构建？

```
1. 收集用户真实 query（从运营反馈、客服记录等）
2. 设计不同难度的测试用例（基础 → 复杂）
3. 搭建简易评估平台（人工评分 + 自动指标）
4. 每次新模型出现 → 批量运行 → 对比结果
5. 持续迭代测试集（业务在变，测试也要变）
```

> 💡 **最佳实践**：测试集 + 评估平台的流程要**标准化**——新模型一出，批量跑一遍就能出结论。

## 九、GRA 评测：高阶能力标杆

GRA（Google 级别的综合评测）代表了 AI 模型评估的高标准，题目特点：

### 典型题目举例

| 题目类型 | 示例 |
|---------|------|
| **知识检索** | "20 世纪唯一一个国籍为已不存在国家的马尔科大获奖者是谁？" |
| **图文结合** | "2015 年大都会博物馆以中国生肖命名的展览中，有多少只动物的手可见？" |
| **视频 + 音频** | "2018 年某 VR 视频中，恐龙首次出现时旁白说了什么数字？" |

### 这些题目考察什么

```
知识问答 ──→ 模型是否具备广泛的知识储备
工具调用 ──→ function call，能否调用搜索/API
多模态理解 ──→ 图片识别、视频逐帧分析、ASR 语音识别
多步推理 ──→ 先检索 → 再分析 → 再综合判断
```

> 💡 **结论**：如果一个模型能通过 GRA 级别的评估，那它距离真正的工作应用就不远了。

```
开始：我有一个 AI 需求
        │
        ▼
  需要自研模型吗？
  ├─ 是 → 你有数千万预算 + 算法团队吗？
  │        ├─ 没有 → 放弃自研，走第三方
  │        └─ 有 → 考虑自研（大厂专属）
  └─ 否 → 使用第三方 API ✅
            │
            ▼
      算经济账：列出所有成本
            │
            ▼
      看榜单：初步筛选 2-3 个候选
            │
            ▼
      实测：团队一起跑评测集
            │
            ▼
      业务测试集：用真实场景验证
            │
            ▼
      选定模型 → 持续跟踪 → 新模型出了就跑一遍对比
```

## 十一、关键术语表

| 术语 | 含义 |
|------|------|
| **H20** | 英伟达面向中国市场的 GPU 芯片，租赁约 3-4 万/月 |
| **Token** | AI 模型处理文本的基本单位，API 按 token 数量计费 |
| **TTS** | Text-to-Speech，文字转语音 |
| **ASR** | Automatic Speech Recognition，语音转文字 |
| **Function Call** | 模型调用外部工具/API 的能力 |
| **Fine-tuning** | 微调，在预训练模型基础上用特定数据继续训练 |
| **SuperCrew** | 公开的 AI 模型评测排行榜平台 |
| **GRA** | 高难度综合评测标准，考察知识 + 工具 + 多模态 + 推理 |
| **评测集** | 一组标准化的测试题目，用于评估模型表现 |
| **一体机** | 预装了 AI 模型的硬件设备（如 DeepSeek 一体机） |

## 十三、学完之后想一想

1. **你现在的项目用的是自研还是第三方 API？** 算过总成本（含隐性成本）吗？
2. **你有自己的业务测试集吗？** 如果没有，能不能从用户真实问题中整理出 50 个？
3. **你关注过哪些评测榜单？** 下次选模型时，试试"算账 → 看榜 → 实测 → 业务验证"四步法。
4. **你的评测流程标准化了吗？** 新模型发布时，你能在多快时间内出对比结论？
