## 一、核心主题一句话

> **工具只是工具——AI 原型的关键不是"从零到一生成"，而是"先抄精品再创新"，把 AI 工具融入你的产品设计 SOP。**

│ 特点：           │ 特点：           │ 特点：           │

│ 适合已有设计师    │ 适合产品经理快速  │ 适合有开发基础的  │

### 各工具特点

| 工具 | 优势 | 局限 | 适合谁 |
|------|------|------|--------|
| **磨刀** | 中文友好，拖拽操作，小孩都能用 | AI 生成仅限简单结构 | 国内产品经理 |
| **Figma** | 专业级，可通过链接还原前端页面 | 中文生态不如磨刀 | 专业设计师 |
| **Frame/UUI** | 手绘线框图 → 自动生成前端页面 | 海外产品，需科学上网 | 快速原型验证 |
| **Lovable** | 自然语言生成完整网站（含交互） | 速度较慢，需科学上网 | 产品经理 / 前端 |
| **V0** | Vercel 出品，生成前端代码 | 能力弱于 Lovable | 前端开发者 |
| **Manus** | 多 Agent 模拟完整团队（PM/架构/测试） | 页面美观度一般 | 快速验证完整方案 |

## 三、零代码原型工具实战

### Lovable 实战体验

**核心能力**：用大白话描述需求 → AI 生成完整网站（不仅是主页，包含所有子页面和交互）

```
你输入："做一个 AI 财务发票管理平台，有上传功能，
       对话功能，历史记录，数据看板"

Lovable 输出：
├─ 首页（上传入口 + 功能导航）
├─ 对话页（新增/清除对话 + 多轮交互）
├─ 数据看板（图表展示）
└─ 设置页（参数配置）
```

**实战数据**：
- 每组约 **10 分钟** 就能搭建一个内部 AI 平台原型
- 可以通过多轮对话持续完善每个子页面的功能细节
- 如果团队动手能力强，配上数据库就能发布完整产品

### 硅基流动 + Lovable = 真·AI 产品

```
1. 在硅基流动（SiliconFlow）生成大模型 API Key
2. 在 Lovable 中绑定这个 API Key
3. 你的原型就能真正调用 AI 大模型 → 从原型变成产品
```

> 💡 **关键发现**：Lovable 生成的原型 + 硅基流动的 API = 一个可以跑起来的小型 AI 产品。月使用成本可能只有几块钱。

## 四、AI Coding 对前端的影响

### 分享者的观点

| 领域 | AI 可替代性 | 原因 |
|------|-----------|------|
| **算法/工程架构** | 较低 | AI 写出来的代码不够优雅，复杂架构驾驭不了 |
| **前端开发** | 较高 | AI 已经能替代约 **2-3 年经验** 前端工程师的水平 |

> "让 AI 编写前端代码，实际上前端工程师的工作有很大的可替代性，甚至某些方面 AI 已经能够替代约 2 到 3 年前端工程师的水平。"

### 对产品经理的启发

- 如果有动手能力，用 Cursor / 灵码 直接写代码实现想法
- Cursor 支持绑定 **MCP 工具**，让 AI 调用外部服务
- 不想写代码，就用 Lovable / V0 等零代码工具

## 五、API 接入与硅基流动

### 硅基流动（SiliconFlow）是什么

一个提供多种大模型 API 的平台，特点是：

| 功能 | 说明 |
|------|------|
| 快速生成 API Key | 注册即可用，方便绑定到其他产品 |
| 多模型可选 | 支持 DeepSeek、Qwen 等多种模型 |
| 模型微调 | 支持 Qwen 2.5 的微调，可上传测试集 |
| 低成本 | 通过邀请可获赠额度，月使用费可能仅几元 |

### 可以绑定硅基流动 API 的产品

| 产品 | 用途 |
|------|------|
| **Cherry Studio** | 本地知识库 + AI 对话 |
| **Chatbox** | 桌面端 AI 客户端 |
| **Lovable** | 零代码原型 → 真正调用 AI |
| 其他支持自定义 API 的产品 | 灵活接入 |

## 六、多 Agent 产品设计：Manus

### Manus 的独特之处

```
你输入一个需求
    │
    ▼
Manus 模拟一个完整团队：
├─ 架构师 Agent → 设计技术框架
├─ 产品经理 Agent → 分析功能设计点
├─ 开发经理 Agent → 规划实现方案
└─ 测试经理 Agent → 考虑测试策略
    │
    ▼
输出：C 端页面 + B 端管理后台 + 全套源码（前后端）
```

### 性价比

| 方案 | 价格 | 说明 |
|------|------|------|
| 免费体验 | 每天 1-2 次 | 体验基本功能 |
| 付费版 | 89 元/周 | 含源码下载 |

> 💡 **商业想象**：89 元买一周使用权，做出一个 5 万元的外包产品——当然，重点不是接外包，而是思考如何用这种 SOP 改变自己的工作方式。

## 七、Claude 的替代方案：Monica

### 为什么需要替代方案？

Claude 在国内无法直接使用，需要科学上网 + 额外费用（约 99 元/月购买特殊服务）。

### Monica：一站式 AI 聚合

| 特性 | 说明 |
|------|------|
| 内置模型 | Claude 4、Sonnet、OpenAI 等 |
| 生图能力 | DALL·E 3、2.5 等 |
| 对话限制 | 不严格 |
| 价格 | 约 800+ 元/年（月均较低） |
| 出品方 | MiniMax 公司 |

> 💡 **适合场景**：想体验 Claude 但又不想折腾科学上网的用户。

## 八、竞品分析与数据采集

### 数据采集的三种方式

```
方式 1：正规数据合作
├─ 与数据服务商（如 Wonder）合作
├─ 合规，但成本高
└─ 适合大公司

方式 2：轻量级 AI 工具采集
├─ 飞书多维表格 → 字段捷径 → 网页链接读取
├─ 输入 URL → 自动提取标题/正文/发布时间
├─ 优点：免费、简单
└─ 局限：有反爬机制的网站效果差（如汽车之家评论）

方式 3：RPA 自动化采集
├─ 影刀 RPA + AI Agent
├─ 可视化搭建采集流程（节点式）
├─ 可以结合 AI 大模型理解采集结果
└─ 适合有一定复杂度的批量采集
```

### 飞书多维表格的实用技巧

| 功能 | 用法 | 效果 |
|------|------|------|
| **网页链接读取** | 新增 URL 列 → 字段捷径 → 自动提取 | 标题、正文、发布时间 |
| **AI 字段** | 指定列 → 调用 DeepSeek 分析 | 情感分析、分类、信息提取 |
| **批量处理** | 1000 条数据 → AI 自动处理 | 用户反馈分类、问题归因 |

### 影刀 RPA + AI 的工作流

```
节点 1：在某页面采集元素 A
    ↓
节点 2：在另一页面采集元素 B
    ↓
节点 3：AI 大模型理解 A+B → 生成分析结论
    ↓
输出：竞品分析报告
```

> 💡 **趋势**：飞书计划整合 RPA 能力，与美团等平台实现数据互通（可能有延迟，但方向确定）。

## 九、AI 行业格局：大厂 vs 小公司

### AI 独角兽的困境

| 现象 | 数据 |
|------|------|
| Kimi 获客成本飙升 | 从 20 元/新客 → 50 元 → 100 元 |
| Kimi 20 天广告投入 | 坊间传闻 1 亿元 |
| 腾讯元宝广告投入 | 一个月数亿（线上线下铺广告） |

### 大厂 vs 小公司的竞争态势

```
大厂（腾讯/字节/阿里/百度）
├─ 算力充足 ✅
├─ 资金雄厚 ✅
├─ 用户基数大 ✅
└─ 不断吸收小公司的创新 → 小公司空间被压缩

小公司/创业公司
├─ 创新速度快 ✅
├─ 算力不足 ❌
├─ 获客成本高 ❌
└─ 只能不断收缩业务范围
```

> 💡 **核心洞察**：做 AI 产品时，"新鲜和创意"不是首要考虑——更重要的是**如何实际融入业务**。大厂会不断壮大，小公司要找与大厂差异化的切入点。

## 十三、学完之后想一想

1. **你现在画原型用什么工具？** 试试 Lovable 或 V0，看看能不能 10 分钟搭出一个原型。
2. **你有在用硅基流动的 API 吗？** 生成一个 API Key，绑定到你常用的 AI 客户端试试。
3. **做竞品分析时，你的数据从哪来？** 试试飞书多维表格的"网页链接读取"功能。
4. **你的产品设计 SOP 是什么？** 有没有可以把 AI 工具嵌入进去的环节？
5. **"先抄再创新"还是"从零开始 AI 生成"？** 在你的项目中，哪种方式更高效？
